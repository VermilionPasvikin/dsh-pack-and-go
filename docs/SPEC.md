# DSH 跨平台迁移助手（暂名 dsh-mover）· 需求规格 v1.2

> 状态：**已冻结 v1.2**（2026-11-11）。v1.0 冻结于 2026-11-10；v1.2 由 ADR-0013 / ADR-0014 / ADR-0015 驱动。
> 冻结规则：需求变更必须先写 ADR（`docs/DECISIONS.md`），再更新本文件并升版本号。
> 一句话：**在任意平台的 DSH 之间，把「对话 + 工作区」打包成一个可离线传输的文件，在另一台机器、另一个平台、另一种 DSH 安装形态里导入并继续使用。**

## v1.2 变更摘要（相对 v1.0，2026-11-11）

| 类别 | 变更 |
|---|---|

## 0. 背景与目标

用户要在**不同平台、不同安装形态的 DSH 之间**搬运工作成果：

1. **跨平台**：Windows ↔ macOS ↔ Linux ↔ WSL，乃至 Termux。
2. **跨安装形态**：DSH Desktop ↔ npm CLI（`dsh web` / `dsh`）↔ 自定义 `DSH_HOME` 部署。
3. 范围覆盖：仅单个对话 / 多个对话 / 多个对话+工作区 / 仅工作区——但**不再由前置“模式”决定**，而是由选择结果自然表达（见 FR-2）。

**关键澄清**：插件的“平台”指 **DSH Host 进程所在的平台**（数据在它的文件系统上），不是浏览器所在平台。远程 Host + 本地浏览器时，迁移的是 Host 的数据。

## 1. 调研结论（源码仓库 + 本机实例）

### 1.1 数据模型与所有权

| 数据 | 位置 | 跨平台结论 |
|---|---|---|
| 会话日志 | `<sessionRoot>/--<归一化cwd>--/<转义 session id>/session.v4.jsonl.zstd` | 目录名由安全字符集构成，**各平台合法** |
| 工作区注册表 | `<DSH_HOME>/storages/workspace.json`（JSON storage domain） | 记录规范化的绝对路径，平台强相关 |
| 附件 | `<DSH_HOME>/attachments/v1`（内容寻址） | 纯字节复制，天然跨平台 |
| 插件与配置 | `<DSH_HOME>/profiles/<name>/` | 按 profile 隔离；**不属于产品数据** |
| 凭据 | `<DSH_HOME>/.credentials.yaml` | 绝不打包 |

**源码事实（`docs/architecture.md`）**：“Desktop 与 npm CLI 共享产品数据，但包、启用选择与锁文件保持独立。” 也就是说：

- 会话/工作区/附件在 `DSH_HOME` 内是**同一份**，Desktop、CLI、Web 看到的是同一批数据；
- profile 只隔离插件依赖、激活列表与配置；
- 因此“换 profile”不是数据迁移问题，**真正的迁移发生在 DSH_HOME 之间、平台之间**。

### 1.2 会话格式与版本

- 当前写入器版本 **v4**（`SESSION_FORMAT_VERSION`）；历史 v0–v3 可通过相邻迁移链读取。
- 物理编码：默认 **Zstandard 多帧**（一帧 header，之后每批事件一帧），也支持 `compression: 'none'` 的纯 JSONL。
- **已提交的 generation 绝不重命名、替换或删除**；写入只能发布新的 generation 路径。
- 目标版本**高于**自身支持时，读取方明确拒绝（“请升级 harness”），不会静默损坏。

### 1.3 跨平台路径规则（v0.2 新增，来自源码）

`packages/session/session-persistence-jsonl/src/format.ts`：

- `encodeSegment(raw)`：只保留 `[A-Za-z0-9._-]`，其余按 **JS UTF-16 code unit** 转 `~XXXX`（大写 4 位），`~` 本身也转义；`.`→`~002E`、`..`→`~002E~002E`。
- `projectKey(cwd)`：把 `/`、`\`、`:` 统一折叠为 `-`（连续合并），其余非法字符 `~XXXX`，去掉前导 `-`，截断 251，外层包 `--…--`；无 cwd 用 `_no-cwd`。
- 结论：**同一路径的 Windows/ POSIX 写法会落到同一个目录键**（因为分隔符都被折叠）；但键基于原始字符串，不做 realpath、不改大小写。

`packages/core/session` 的 header 校验使用 `node:path` 的 `isAbsolute`：

- 在 Linux/macOS 上，`isAbsolute('C:\\x') === false` → 带 Windows cwd 的会话头会被判为**非法 header，会话无法打开**。
- 因此 **Windows → POSIX 必须改写 cwd**；反向（POSIX → Windows）虽然能通过绝对性检查，但 cwd 指向不存在路径，工作区归属也会失败。

`packages/workspace/workspace/src/paths.ts`：

- `fullyQualifiedWorkspacePath`：win32 要求盘符绝对路径（拒绝 `\`、`/` 根、`C:work`）；POSIX 要求 `posix.isAbsolute`。
- `realpathNormalize`：工作区路径必须**已存在**，经 `realpath` 规范化；唯一性 = 规范化字符串相等（符号链接会碰撞）。

### 1.4 工作区与会话归属

- 工作区是“目录 + 标题”的持久记录；**会话按目录归组**：会话 `cwd` 解析到工作区目录，才落到该工作区。
- 导入后要让会话出现在侧边栏，必须同时满足：会话头 cwd = 目标平台上的**真实存在目录**；且该目录已登记为工作区。

### 1.5 附件

- 存在 `<DSH_HOME>/attachments/v1`，内容寻址、同内容只存一份，永不被自动删除。
- 官方文档明确其定位是“本机对象”，不提供跨机同步 → 迁移工具需要自己复制被引用的对象。

### 1.6 `DSH_HOME` 与安装形态

- `resolveDshHome()`（`@deepseek-ai/dsh-home-paths`）：`$DSH_HOME` 非空则用之，否则 `~/.dsh`，支持 `~` 展开。
- **所有平台默认 `~/.dsh`**；但可被环境变量、容器部署、Python SDK 的 `dshHome` 覆盖为任意路径。
- 会话持久化 `root` 是配置项（必填），随附组合默认在 `DSH_HOME` 下，但**不能假设**；实现必须通过 `sessionPersistence.list()` 快照里的 `location.path` 获取真实绝对路径。

### 1.7 能力缺口（仍然成立）

DSH 没有“会话/工作区导入导出”的官方能力（只有单会话日志下载）；没有跨机同步；没有文件复制 API。插件必须自己完成：文件搬运、header 改写、工作区登记、平台兼容处理。

## 2. 名词

| 名词 | 含义 |
|---|---|
| 源 Host / 目标 Host | 产出迁移包的 DSH 进程所在平台；接收并导入的 DSH 进程所在平台 |
| 源平台 / 目标平台 | `win32` / `darwin` / `linux`（WSL、Termux 归入 linux，标注差异） |
| 对话 | 一个 Session（历史、标题、模型选择、关联附件） |
| 工作区 | 侧边栏中的项目目录记录（路径 + 标题 + 其下会话） |
| 工程目录 | 工作区对应的真实文件夹 |
| 路径映射 | 源平台的旧路径 → 目标平台的新路径 |
| 迁移包 | 单文件 `.dshpack` |

## 3. 目标用户与场景

**主要用户：0 技术背景小白**。只会点按钮、拖文件、看进度条、读中文提示。

| # | 场景 | 操作 | 期望 |
|---|---|---|---|
| S1 | Windows 台式机 → MacBook | 导出「对话+工作区」 | 新电脑导入后侧边栏出现同名工作区与全部对话，能继续问 |
| S2 | macOS → Windows | 同上 | Windows 非法文件名、大小写冲突被自动处理并汇报 |
| S3 | Linux 服务器（CLI，无 GUI）→ Windows 桌面 | 服务器上用命令行导出，Windows 上 UI 导入 | 包格式一致，双向可读 |
| S4 | 只带一个对话去另一台机器 | 导出「单个对话」 | 导入后可打开历史；若目标无对应工作区，引导归入某工作区 |
| S5 | 只备份项目文件（非 DSH 用户也能打开） | 导出「仅工作区」 | 包内是标准可解压的项目文件 |

## 4. 跨平台支持矩阵与范围

| 级别 | 平台 | 说明 |
|---|---|---|
| **一级（必须支持）** | Windows 10/11（x64/arm64）、macOS 12+（Intel/Apple Silicon）、Linux x64/arm64 | 完整功能 |
| **二级（尽力支持）** | WSL2（`/mnt/c` 与 Linux 根文件系统）、Termux/Android | 根据平台差异提示限制 |
| **明确不支持** | 无本地 `DSH_HOME` 的纯远端托管场景 | 迁移应由 Host 侧完成；插件不跨网络拉取 |

**迁移方向必须双向**：Windows→POSIX、POSIX→Windows、macOS↔Linux、同平台不同安装形态。

## 5. 功能需求

### FR-1 入口与页面

- DSH Web UI 侧边栏常驻图标 → 打开「对话与工作区迁移」页面（`main` 面板）。
- 设置 → 插件 下提供备用入口。
- 页面顶部始终标注：**当前平台**、`DSH_HOME` 路径、DSH 版本。
- 自适应明暗主题、字号、中英文案。

### FR-2 选择模型：一棵「工作区 → 对话」树（v0.3 重写）

**不再使用前置的“四种模式”卡片。** 四种范围是选择结果的**自然表达**，而不是让用户先做一次抽象选择：

| 用户意图 | 怎么点 |
|---|---|
| 只带走一个对话 | 展开工作区 → 只勾那个对话（“含项目文件”保持关闭） |
| 带走多个对话 | 在多个工作区下各勾若干对话 |
| 带走对话 + 项目 | 勾工作区（默认全选其对话）→ “含项目文件”默认打开 |
| 只带走项目 | 勾工作区 → 点行内「只带文件」（取消对话、打开文件开关） |

树的结构完全对齐 DSH 侧边栏：

- 一级：**工作区**（标题、路径、对话数、项目大小）
- 二级：该工作区下的**对话**（标题、最后活动、大小）
- 虚拟分组「未归入工作区」（DSH 原生也允许对话不属于任何工作区）
- 已归档对话默认隐藏，行尾「显示已归档」可展开

**勾选语义**：

- 勾工作区 = 选中该工作区记录 + 默认全选其下未归档对话；用户可再取消个别对话，工作区行变为“部分选中”。
- 只勾部分对话时，仍会带上该工作区的元数据（用于导入后正确归组），但**不带项目文件**。
- “含项目文件”是**全局一个开关**（不是每个工作区一个）：同一类决策只问一次；开关旁实时显示 `约 840 MB`。
- 联动：未选中任何工作区时文件开关自动置灰；勾选工作区时默认打开。

**底部固定栏**（始终可见）：

```
已选 1 个工作区 · 3 个对话 · 含项目文件约 840 MB（总计约 862 MB）
[ 开始打包 ]   [高级选项]
```

- 未选中任何内容时主按钮禁用，提示“至少选择一个对话，或勾选一个工作区并打开项目文件”。
- 大小估算 300ms 内更新；大工作区只做一次元数据扫描并缓存。

**其他选择能力**（不占主界面）：

- 搜索框：按对话标题过滤（对话超过 20 个时出现）。
- 行内「只带文件」快捷操作（工作区行悬停出现）。
- 「显示已归档」小开关（默认关）。

**「仅工作区」模式（v1.2 新增，ADR-0015）**：

- 导出页顶部提供模式切换：「对话 + 工作区」（默认）/「仅工作区」；
- 「仅工作区」模式只列出工作区（含空文件夹工作区），导出工作区内容与目录结构（`mode='workspaces'`、`sessions=[]`），不导出任何对话；
- 至少选择一个工作区才能开始导出；导入端按空工作区登记（见 FR-8）。

### FR-3 选择对象的数据来源（v0.3 补充）

- 工作区与对话都来自 DSH 原生服务（`workspaceRegistry` / `workspaceController` / `sessionQuery`），不自行扫描目录，保证与侧边栏一致。
- 会话“大小”优先取持久化快照的 `sizeBytes`；缺失时用一次轻量元数据扫描补齐（不读正文）。
- 排序沿用 DSH：工作区按原生顺序，对话按最近活动，置顶在前。
- 空状态：`还没有可迁移的内容` + 一句引导；加载态用骨架屏，不阻塞页面。

### FR-4 可见控制清单（v0.3 重写）

**主界面只保留两类控制**：选什么、是否含项目文件。其余全部使用推荐默认值。

| 控制项 | 可见性 | 默认值 |
|---|---|---|
| 工作区/对话勾选树 | 主界面 | — |
| 含项目文件 | 主界面（一个开关） | 勾了工作区则开 |
| 搜索、显示已归档、只带文件 | 次要（行内/超过阈值才出现） | 关 |
| 排除规则 | 高级折叠 | 排除 `node_modules`、`.venv`、`venv`、`__pycache__`、`.pytest_cache`、`dist`、`build`、`out`、`.next`、`coverage`、`.cache`；`.git` 保留 |
| 压缩级别 | 高级折叠 | 平衡 |
| 跨平台预检 | 高级折叠 | 开；只在有风险时主界面显示一行摘要 |
| 附件 | 高级折叠 | 开 |
| 机器名、校验和、并发 | 高级折叠 | 记录机器名 / 包级校验 / 自动 |

### FR-5 打包执行与进度（沿用 v0.1）

- 阶段：`扫描文件 → 平台预检 → 打包对话 → 打包工作区 → 生成校验 → 完成`。
- 总进度条 + 当前文件 + 已写入/总量 + 已用时间 + 取消。
- ≤300ms 出现进度；≤500ms 刷新。
- 完成页：路径、大小、耗时、清单摘要；按钮「打开所在文件夹」「复制路径」。

### FR-6 导入：选择与校验（v0.2 增强）

- 拖入或点选 `.dshpack`。
- 校验：包结构、manifest、`schemaVersion`、**源平台**、会话格式版本、可选的校验和。
- 校验失败中文说明原因与下一步（例如“包来自更新的 DSH 版本，请先升级本机 DSH”）。

### FR-7 导入：清单预览（v0.2 增强）

- 来源：打包时间、源平台、源 DSH 版本、来源机器名（可关闭）。
- 对话列表（标题、所属工作区、消息数、时间）。
- 工作区（名字、原路径、文件数/大小、排除项）。
- 附件数量与大小。
- **跨平台差异摘要**：`源平台 Windows → 本机 macOS；3 个文件名需要转换；1 个符号链接；将重建 2 个权限位`。
- 冲突提示：同 id 会话、同路径工作区。

### FR-8 导入：落点与路径映射（v1.2 重写，ADR-0013）

- **目标目录必填**：导入必须指定一个目标目录（默认预填 `~/dsh-mover-import`），不提供「放回原路径」。
- 每个包内工作区映射到 `<目标目录>/<工作区标题>`；目标目录下同名目录已存在时复用已登记工作区，未登记的非空目录自动加序号（`标题 (1)`）；空目录视为本插件遗留目录直接复用。
- 自动生成**路径映射表**：`旧路径 → 新路径`，覆盖所有会话 cwd、工作区记录。
- 明确告知：历史消息中的旧路径文字不会改写（只影响显示，不影响继续对话）。
- **仅对话导入**：会话归属由包内 workspaceKey + 目标目录决定；无 workspaceKey 的会话保留源 cwd（未分组）。
- **空工作区**：包内无会话的工作区也登记并还原文件（结果标注「暂无对话」）。

### FR-9 文件系统兼容预检与转换（v0.2 新增）

导入前对每个工作区文件做目标平台合法性检查，并提供**可预览、可撤销**的处理：

| 风险 | 默认策略 |
|---|---|
| 非法文件名（Windows） | 自动安全重命名（`?`→`_` 等），在清单中逐项列出；提供“跳过该文件”选项 |
| 大小写冲突 | 保留第一个，其余重命名加后缀；列出冲突组 |
| 路径过长（Windows） | 尝试启用长路径；失败则跳过并报告 |
| 符号链接 | 默认**解引用为普通文件**（体积可能变大）；可选“保留链接”或“跳过” |
| POSIX 权限位 | 有 exec 位的文件在 POSIX 目标恢复 `755`；Windows 目标忽略并记录 |
| 文件名编码 | 统一 UTF-8；无法解码的条目报告为跳过 |
| 空目录 | 保留（可在清单中显示） |

- 转换结果写入包内映射表，导入完成后可导出「转换报告」。
- **默认不静默丢弃任何文件**：跳过必须出现在报告里。

### FR-10 冲突处理（v1.2 重写，ADR-0013/ADR-0014）

- 会话同 id 已存在：**跳过** / **覆盖**（已移除「另存为新对话」）。
- 覆盖 = 原地恢复（目标 cwd 与现有 cwd 相同）；目标 cwd 不同时**迁移覆盖**：备份并移除旧位置目录、写入目标位置，结果提示「原工作区/会话 → 新工作区/会话」。
- 覆盖但现有会话 cwd 未知：拒绝覆盖并报错（安全优先）。
- 工作区同路径已存在：复用/合并；文件同名覆盖并统计。
- 覆盖前自动备份到 `<DSH_HOME>/dsh-mover-backup/<时间戳>/`。

### FR-11 执行与进度（沿用 v0.1）

阶段：`校验 → 恢复对话（含 cwd 改写）→ 恢复附件 → 恢复工作区（含文件名转换）→ 登记工作区 → 完成`。
不删除任何现有文件；写入采用临时文件 + 原子替换。

### FR-12 生效与提示（v1.2 修订）

- 尽量让新对话/工作区立即出现（激活 + 广播）。
- DSH 内存中的会话与启动索引不会因覆盖自动刷新：导入前已打开的会话需**重启 DSH**；迁移覆盖的新位置需重启 DSH 后出现在左侧；空工作区同理——结果文本逐项提示。
- 必须重启时明确提示，**绝不擅自重启**。

### FR-13 附件（沿用 v0.1）

按引用复制，不复制无关对象；缺失附件单独报告，不阻断其他内容。

### FR-14 分支 / 子会话（沿用 v0.1）

默认连带 fork 链与子代理会话，可关闭并提示丢失范围。

### FR-15 错误与恢复（v0.2 增补）

每条错误给：中文原因 + 影响 + 下一步。新增跨平台错误：平台不支持、路径非法、文件名冲突无法自动解决、符号链接创建失败、格式版本过旧/过新、磁盘空间不足、目标目录不可写。

### FR-16 记录与诊断（低优先，沿用 v0.1）

最近 5 次导出/导入记录；可导出不含隐私的诊断 JSON。

## 7. 非功能需求

### NFR-1 易用性（v0.3 补充）

不需要命令行、不需要看懂路径；每页一个主按钮；危险操作二次确认；全中文（附英文 locale）；首次使用 3 行引导。

#### NFR-1.5 最小参数暴露（v0.3 新增，可验收）

- 主流程只允许两类可见控制：**选什么**、**是否包含项目文件**（导入侧为“是否解压项目文件”）。
- 以下参数默认隐藏，只在“高级”折叠或异常时出现：路径映射、排除规则、压缩级别、冲突策略、平台转换策略、机器名、校验和、并发数。
- 任何新增可见参数必须证明其影响 95% 以上的使用场景；否则必须提供推荐默认值并隐藏。
- **验收方式**：找一位没读过文档的人，从“导出”到“在另一台机器导入”全程不应展开“高级选项”。

### NFR-2 性能（沿用 v0.1，跨平台不降级）

| 操作 | 数据量 | 目标 |
|---|---|---|
| 导出（仅对话） | 50 会话 / 200 MB | ≤ 10 s |
| 导出（对话+工作区） | 500 MB | ≤ 60 s |
| 导出（对话+工作区） | 2 GB | ≤ 4 min |
| 导入 | 同量级 | 不超过导出耗时的 150% |
| 跨平台预检 | 10 万文件 | ≤ 5 s（纯元数据，不读内容） |
| 首屏 | 100 工作区 / 500 会话 | ≤ 1 s |

- 流式读写，内存峰值 ≤ 300 MB 且与工作区大小基本无关；Host 主线程不做长同步计算。

### NFR-3 进度可视化（沿用 v0.1）

超过 2 秒的操作必须有进度与阶段文字；通过 Host → Client 流式推送，不轮询。

### NFR-4 安全与隐私（沿用 v0.1 + 跨平台补充）

- 绝不打包：`.credentials.yaml`、任何 key/token、`cache`、`llm-deepseek`、`profiles/*/node_modules`、`dsh-runtimes`、`electron`。
- 导入拒绝路径穿越与绝对路径条目；解压目标必须在用户选定目录内。
- 覆盖前备份；不自动删除。
- **跨平台补充**：包内不记录凭据类路径；机器名可关闭；转换报告不包含文件内容。

### NFR-5 兼容性（v0.2 重写）

- **平台矩阵**：见 §4；不支持的组合（如无本地 DSH_HOME）明确拒绝。
- **DSH 版本**：manifest 记录 DSH 版本 + 会话格式版本；目标版本过旧时拒绝并提示“请升级 DSH”，不静默降级。
- **会话格式**：v4 写入；读取历史包时若目标支持迁移链则可用，否则提示。
- **路径**：所有包内路径用 `/` 分隔；导入时按目标平台重建；manifest 保留原始路径字符串用于显示。
- **文件**：保留 POSIX 权限位与 mtime（格式支持时）；Windows→POSIX 的 exec 位默认 644，脚本可手动 `chmod`。
- **Node/Electron**：zstd 使用运行时内置能力，启动时做特性检测；缺失时降级为“不压缩 + 提示”。

### NFR-6 可靠性（沿用 v0.1）

临时文件 + 原子替换；导入幂等；离线单文件；中断可重试。

## 8. 迁移包格式 `.dshpack` v2（v0.2 调整）

单文件（zip 容器，兼容普通解压工具），内部路径统一 `/`：

## 9. 技术方案要点与风险（v0.2 重写）

### 可行的做法

1. **路径不硬编码**：从 `ctx.sessionPersistence.list()` / `stat()` 快照的 `location.path` 取会话文件真实绝对路径；从 `ctx.workspaceRegistry.list()` 取工作区记录；从 `attachment` 服务或 `DSH_HOME` 配置取附件根。
2. **导出 = 文件复制 + 元数据**：不解析会话内容即可打包（除附件引用扫描与 cwd 读取）。
3. **导入 = 文件写回 + cwd 改写 + 工作区登记**：
   - 同平台同路径：直接复制，零解析；
   - 跨平台/改路径：解出第一帧 header、改 `cwd`、重压缩、拼接其余帧（需要 zstd 帧扫描）；
   - 工作区用 `workspaces.create({path})` 登记（路径必须已存在且合法）。
4. **会话写入**：写新的 generation 文件（不覆盖已提交文件）；同 id 冲突时按 FR-10 处理。
5. **进度**：Host `@Remote({ mode: 'stream' })` 推送；Client 订阅。
6. **UI 入口**：`sidebar.panellist` + `ctx.layout.selectPanel('mover')`；页面注册在 `main` slot（key `mover`）；备用 `settings.section`。

### 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| header cwd 改写出错 | 会话打不开 | 改写后解回校验 header 与行数；失败回滚；原文件不动 |
| zstd 帧扫描实现错误 | 会话损坏 | 单元测试覆盖多帧/尾帧/RLE/checksum；与官方实现对照 |
| 平台文件名冲突 | 导入失败或丢文件 | FR-9 预检 + 自动重命名 + 报告；绝不静默跳过 |
| 活跃会话写锁 | 导入失败 | 检测活跃会话；提示先结束；导出只读 |
| 目标 DSH 版本过旧 | 会话无法读取 | manifest 版本校验，提前拒绝 |
| 工作区巨大 | 耗时/空间 | 默认排除再生目录 + 预估 + 可取消 |
| 远程/虚拟文件系统 | 性能与一致性 | 检测并警告；不支持则拒绝 |
| 权限位/符号链接差异 | 行为不一致 | 显式策略 + 报告 |

## 11. 验收标准（可测试）

1. 侧边栏入口 2 秒内打开页面；明暗主题正常；中英文案完整。
2. 选择模型验收：勾一个工作区默认全选其对话；取消部分对话后仍可导出；「只带文件」只导出项目；只勾对话可导出且导入后正确归组；未归入工作区的对话可选。
3. 500 MB 工作区导出进度完整，取消后清理临时文件。
4. **跨平台验收**：在一次性 `DSH_HOME`（`%TEMP%` 或 `/tmp`）中模拟：
   - Windows 包 → 用 POSIX 规则校验：会话 header cwd 已改写、`isAbsolute` 通过；
   - 含 Windows 非法文件名的包 → 导入预检报告并自动重命名；
   - POSIX 大小写冲突包 → 冲突被检测并处理。
5. 导入后工作区与对话出现在侧边栏，会话可打开、可继续发消息（界面与历史正常）。
6. 同 id 会话重复导入默认不产生重复。
7. 截断/篡改包在导入前被拒绝，给出中文说明。
8. 大工作区导出内存峰值 ≤ 300 MB。
9. 包内不含凭据/缓存/node_modules（检查脚本断言）。
10. 转换报告覆盖每一个被重命名/跳过/解引用的条目。
