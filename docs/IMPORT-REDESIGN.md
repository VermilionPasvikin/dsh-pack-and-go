# 导入模式重设计方案（待用户选择）

> 背景：现有导入把「落点」（原路径/指定目录）与「冲突策略」（跳过/另存为新对话）作为两组独立单选，
> 但两者的组合语义不一致：「另存为新对话」走 DSH fork，**保留源 cwd**，使「指定目录」实际失效，
> 用户难以理解。本方案重构导入阶段的交互模型。

## 一、现状问题清单

| # | 问题 | 现象 |
|---|---|---|
| 1 | 无效组合 | 「指定目录 + 另存为新对话」：会话仍落回原工作区 |
| 2 | 概念混用 | 「落点」与「冲突处理」被并列成两组单选，用户不知道谁影响谁 |
| 3 | 默认不明确 | 默认「放回原路径 + 跳过」在同机重复导入时几乎什么都不做，但用户不知道 |
| 4 | 结果不可预期 | fork 保留 cwd、跳过的会话不复制、覆盖不提示——行为分散 |
| 5 | 缺少结果汇总 | 导入前没有"将发生什么"的明确摘要（谁被跳过、谁覆盖、文件去哪） |

## 二、方案 A：两步向导（先落点、再冲突）

**交互**：导入页分两个区块，顺序固定：

1. **「放到哪里」**
   - ◦ 新位置（默认，目录选择器，默认 `~/dsh-mover-import`）
   - ◦ 原位置（仅当包来源平台可用；跨平台时禁用并提示原因）
2. **「已存在的对话」**
   - ◦ 跳过（保留现有，默认）
   - ◦ 覆盖（用包内版本替换）
   - （移除「另存为新对话」）
3. 底部一行摘要：「将导入 13 个对话、1 个工作区到 `<路径>`；跳过 0 个已存在」

**优点**：组合减少（2×2 → 2×2 但语义清晰）；每个选项效果单一可解释。
**缺点**：失去同机复制对话能力；需把「复制」作为独立入口。

## 三、方案 B：意图驱动（先选目标，再自动给参数）

**交互**：导入页第一步选「你想做什么」：

1. **迁移到这台电脑**（默认）→ 新位置 + 跳过/覆盖
2. **恢复/合并回原位**（同机恢复）→ 原路径 + 跳过/覆盖
3. **复制一份对话**（同机复制）→ 走 fork，复制到当前工作区，不显示目录选择

**优点**：用户按意图选择，不会遇到无效组合；复制与迁移彻底分离。
**缺点**：多一步选择；「迁移」与「恢复」对小白仍需要一句解释。

## 四、方案 C：智能默认 + 高级折叠 + 独立复制（推荐）

**交互**：

- 导入页默认只有一行：**「导入到新位置（默认 `~/dsh-mover-import`）」+「开始导入」**；
- 「高级选项」折叠内：
  - 落点：新位置（可改目录）/ 原位置
  - 已存在：跳过（默认）/ 覆盖
- 导出页/选择区新增独立操作：**「复制对话到当前工作区」**（单选对话后可用，走 fork，语义为"复制"而非"导入"）；
- 预览卡片保留：来源、数量、冲突数，并显示**将执行的动作摘要**。

**优点**：零参数可用（符合 SPEC 最小参数）；无效组合消失（复制不在此流程）；高级用户仍可控。
**缺点**：复制功能位置变化（需要用户知道在导出页）。

## 五、方案 D：冲突列表逐项处理（高级工具，不推荐首选）

预览后列出每个冲突（同名工作区/同 id 会话），逐项选择跳过/覆盖/复制。灵活但 UI 复杂，
违背"小白友好"，建议作为后续「高级合并」功能。

## 六、对比

| 维度 | A 两步向导 | B 意图驱动 | **C 智能默认（推荐）** | D 逐项 |
|---|---|---|---|---|
| 小白易懂 | 中 | 高 | 高 | 低 |
| 无效组合 | 无 | 无 | 无 | 无 |
| 参数数量 | 中 | 少 | 最少 | 多 |
| 复制对话 | 独立入口 | 意图之一 | 独立入口 | 逐项 |
| 实施成本 | 中 | 中 | 低-中 | 高 |

## 七、推荐

**方案 C**，理由：

1. 默认「新位置 + 跳过」覆盖 90% 迁移场景（换机/新 profile）；
2. 「原位置」与「覆盖」收进高级选项，普通用户无需理解；
3. 「复制对话」从导入流程剥离，消除 fork 与落点的语义冲突；
4. 与现有 UI 结构（预览卡片、结果文本）兼容，改动集中。

## 八、需要用户拍板

1. 选 A / B / C / D 哪个方案？
2. 「另存为新对话」是否接受改名为「复制对话到当前工作区」并移到导出页/选择区？
3. 默认目标目录是否保持 `~/dsh-mover-import`，还是改为"上次使用的目录"？
